5. Google Calendar collector (required path for this tutorial)

Use Google Calendar as the source of truth for “Coming up.” Do not scrape a logged-in browser as the primary method. Prefer one of these:

Option A — Google Calendar API (recommended for multi-calendar households)

  1. Create a dedicated shared family calendar in Google Calendar (not your personal work calendar).
  2. In Google Cloud Console, create a project, enable the Calendar API, and create credentials (OAuth for a user script, or a service account if you prefer and understand sharing).
  3. Store client secrets / tokens in a local file outside git (for example ~/.config/family-daily/google-credentials.json). Add that path to .gitignore.
  4. Your collector script lists events for “today + a few days” and emits structured JSON for the HTML template.
# Pseudocode — you write the real script
# 1. Load credentials from a local path (never hard-code)
# 2. calendar.events().list(calendarId="YOUR_FAMILY_CALENDAR_ID", ...)
# 3. Write /tmp/family-daily-events.json for the template

Option B — Secret iCal / .ics feed URL

  1. In Google Calendar settings for the shared family calendar, copy the private iCal address if you use that feature.
  2. Store the full URL in a local env file, e.g. FAMILY_ICAL_URL=...—not in the repo.
  3. Collector does a simple HTTPS GET and parses VEVENT entries.
# Local env file (do not commit)
# FAMILY_ICAL_URL=https://calendar.google.com/calendar/ical/EXAMPLE/private-PLACEHOLDER/basic.ics

curl -fsSL "$FAMILY_ICAL_URL" -o /tmp/family.ics
# parse with icalendar / a small Python script → JSON for the paper
Never publish the iCal URL Treat it like a password. Rotate it if it ever leaks. This guide only shows placeholder URLs.

6. Publish + wake schedule

Editions usually map to morning / afternoon / evening, with an optional hourly “live wire” if you add chat later. Configure the server so the frame wakes after each edition publishes. Conceptually:

# Config idea (exact key names: check your hokku-server version)
"refresh_image_at_time": ["0815", "1530", "1945"]

Order of operations: generate → publish → verify landing → then the wake times fire. If you wake before the PNG is ready, the frame may show yesterday’s paper.

Schedule your publish script with cron or launchd a few minutes before each wake, for example:

# crontab sketch (host-local)
10 8 * * *  /Users/YOU/bin/publish-family-daily morning
25 15 * * * /Users/YOU/bin/publish-family-daily afternoon
40 19 * * * /Users/YOU/bin/publish-family-daily evening

7. Editorial rules (kitchen audience)

  • Audience: people glancing while making coffee—not ops dashboards.
  • No secrets on the wall: no passwords, pay, brokerage, account numbers.
  • Changes: useful deltas only. Skip “nothing changed” filler.
  • No ops jargon on the paper (“pipeline green” belongs in logs, not breakfast).
  • Coming up: calendar-driven.
  • Resolved loops: let finished items decay in about 1–2 days.
  • Correctness before publish: if the collector fails, don’t push a half-blank edition—fail loud on the host instead.

8. Verify landing

Before you walk away:

  1. PNG mtime is fresh.
  2. Hokku convert / processing status is ok.
  3. show_next points at the new file.
  4. Optional after wake: last_seen updated.

Troubleshooting

SymptomThings to try
Frame never updates Confirm server is up; wake times are after publish; frame and host share a LAN; check last_seen after a wake window.
Image looks cropped Revisit scale-to-fill without side crop; increase safe margins (~40px); stick to 1200×1600.
Convert status not ok Hard-fail the publish script; inspect the PNG; re-render; do not pin show_next until status is ok.
Calendar empty Verify family calendar ID / iCal env var locally; check API quota and token refresh; don’t fall back to browser scraping.
Wi‑Fi flash failed Re-read upstream flash docs; double-check SSID locally; 2.4 GHz vs 5 GHz quirks are device-specific—follow Hokku’s hardware notes.
