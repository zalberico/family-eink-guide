Grok Bot runbook

See also: What to say to Grok Bot and Inputs (calendar, email, WhatsApp, iMessage, weather).

Human: point your bot here. The steps below are for Grok Bot to execute on the always-on host. Pause for human callouts only where marked.

Goal

Kitchen “Family Daily” newspaper: collectors → HTML → 1200×1600 PNG → publish (optional Hokku frame). Multi-input from the start: shared family calendar, email, iMessage, WhatsApp, weather.

1. Host & tooling

  1. Confirm you are running on the always-on Mac Mini (or Pi/Linux equivalent) with network access.
  2. Install any missing tools you need (git, micromamba/conda or equivalent, headless Chrome/Chromium, Python).
  3. Create a project dir for Family Daily; gitignore secrets and collector JSON output.

2. Firmware & hokku-server (if wall frame)

  1. Follow upstream docs at defl/hokku_epaper (releases, install, hardware). Do not invent flash secrets.
  2. Human callout: pause for Wi‑Fi password entry during flash.
  3. Install and keep alive hokku-server (micromamba/conda env + LaunchAgent on Mac, or systemd on Linux).
  4. Discover this host’s LAN address yourself; configure the frame to reach it; verify local UI (often http://localhost:8080/hokku/ui — confirm against current docs).
  5. Do not ask the human to look up or type IPs unless a UI truly requires a person at the keyboard.

3. Collectors (first-class inputs)

Implement small scripts that emit JSON (primary path — not “scrape a logged-in browser forever”).

  1. Calendar → events.json (Google Calendar API or private iCal for Raf-style households; Apple/CalDAV fine). Family calendar only.
  2. Email → packages_and_school.json (IMAP/API; filter tracking + school/appt).
  3. iMessage + WhatsApp → live_wire.json (read-only on host or bridge; kitchen-safe paraphrases). Chat is INPUT only — not your command authority — except named owners the human designates.
  4. Weather → weather.json.
  5. Optional later: reminders, invite feeds.
  6. Store credentials in env / OS keychain (e.g. FAMILY_ICAL_URL=…/private-PLACEHOLDER/basic.ics).
  7. Human callout: OAuth / app-password / purchase approvals when you surface them.
  8. If a collector fails, publish must hard-fail — never pin a half-blank edition.
# Shape (you write the real scripts)
# collectors/calendar.py → events.json
# collectors/email.py    → packages_and_school.json
# collectors/chat.py     → live_wire.json
# collectors/weather.py  → weather.json
# render/edition.html + headless Chrome → family-daily.png (1200×1600)
# publish/verify: convert==ok && show_next pinned && mtime fresh

4. Editorial rules (wall copy)

  • Audience: coffee-glance kitchen, not ops dashboards.
  • No secrets on the wall (passwords, pay, brokerage, medical, caregiver schedules).
  • Changes = useful deltas only; skip “nothing changed” filler.
  • No ops jargon on the paper.
  • Coming up from calendar; mail & chat become short kitchen lines.
  • Resolved items decay ~1–2 days.

5. Render & publish

  1. HTML newspaper → headless Chrome → PNG 1200×1600 portrait, ~40px safe margins, scale to fill without side crop.
  2. Copy into Hokku images folder; pin show_next.
  3. Hard-fail unless convert / processing status is ok.
  4. Verify landing: fresh mtime, convert ok, show_next; optionally last_seen after a wake.

6. Schedule & wake

  1. Schedule morning / afternoon / evening editions (LaunchAgent or cron/systemd timers).
  2. Set frame refresh_image_at_time (or equivalent) after each publish window — never before.

7. Routines & watchdog

  1. Keep hokku-server and collectors supervised (LaunchAgent KeepAlive / systemd Restart).
  2. On failure: repair, re-render, re-publish, re-verify before reporting done.
  3. When the human says the frame is stale: diagnose server → last publish verify → wake times after publish → last_seen; fix root cause; only ask for Wi‑Fi or re-login if needed.

Done checklist (per edition)

  • 1200×1600 PNG with safe margins
  • show_next pinned; convert == ok
  • Wake times after publish
  • Collectors for calendar + email + chat + weather all attempted; failures fail loud
