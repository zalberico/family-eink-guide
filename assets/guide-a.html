What you’ll build

Imagine a quiet newspaper on the kitchen wall: today’s weather, what’s coming up, and only the changes that matter. No glowing tablet. No password prompts. Just a portrait e-ink panel that wakes a few times a day, pulls a fresh PNG from a home server, and goes back to sleep.

This guide teaches the pattern behind one real setup. Names, appointments, and network details below are placeholders (Alex & Sam, YOUR_WIFI, 192.0.2.x). Fill in your own secrets on your machine—never commit them to git or paste them into a public gist.

Privacy first Keep passwords, brokerage, pay, and caregiver details off the wall. The board is for a kitchen audience. Sample content in this guide is fictional on purpose.

Architecture

Think of it as a tiny newsroom:

  1. Collectors pull calendar, weather, and (optionally) chat / package mail.
  2. HTML newspaper lays out a portrait “edition.”
  3. Headless Chrome renders that HTML to a 1200×1600 PNG (safe margins ~40px; scale to fill without cropping the sides).
  4. Publish script copies the PNG into the Hokku images folder, pins show_next, and refuses to call it done unless convert status is ok.
  5. hokku-server serves the image; the frame wakes after editions publish (config like refresh_image_at_time).

On a Mac-style host, runtime data often lives under an application-support style folder for Hokku (images, cache, config). The local UI is typically something like http://localhost:8080/hokku/ui—confirm against the current Hokku docs for your version.

Step-by-step

1. Buy the frame

Get a Hokku or Huessen 13.3″ Spectra 6 (ESP32-S3). Check the public repo’s hardware guide so you know which revision you’re holding before you flash.

2. Flash Hokku firmware

Follow the official install path in defl/hokku_epaper (releases + install docs). When the flasher asks for Wi‑Fi, enter your network locally. Do not screenshot or commit those values.

Placeholder habit In notes and scripts, write YOUR_WIFI_SSID and YOUR_WIFI_PASSWORD. Real values stay on the machine that flashes the board.

3. Run hokku-server

Install and run the Python server from the Hokku project. A common pattern on macOS is a micromamba (or conda) env named something like hokku, plus a LaunchAgent (or systemd unit on Linux) so the server survives reboots.

# Example shape only — adjust paths to your machine
micromamba activate hokku
# then start hokku-server per upstream docs

# Keepalive idea (macOS LaunchAgent): a plist that relaunches the server
# Keepalive idea (Linux): systemd user service with Restart=always

Open the local UI in a browser on the host (often around port 8080 under a /hokku/ui path). Confirm the frame can see the server on your LAN using documentation-recommended discovery—not by publishing your real LAN IP. In examples, use documentation ranges like 192.0.2.10.

4. Generate the newspaper PNG

Target size: 1200×1600 portrait PNG. Render HTML with headless Chrome, then scale to fill without cropping the left/right edges. Leave roughly 40px of safe margin so text doesn’t kiss the bezel.

# Sketch of a render step (paths are yours)
google-chrome --headless --disable-gpu \
  --screenshot=/tmp/family-daily.png \
  --window-size=1200,1600 \
  "file:///PATH/TO/edition.html"

# Then scale with your preferred tool so content fills height
# without cropping sides — ImageMagick, Pillow, etc.

Your publish script should:

  • Copy the PNG into the Hokku images directory.
  • Pin / set show_next so the frame knows which file to pull.
  • Hard-fail if convert status is not ok.
  • Verify “landing”: fresh file mtime, convert ok, and show_next pointing at the new image—before you call the run done.
  • Optional: after a scheduled wake, check last_seen to confirm the frame actually checked in.
