What you’ll build

A quiet newspaper on the kitchen wall: weather, what’s coming up, packages and school notes from email, a short live wire from household chat, and only the changes that matter. Portrait e-ink, a few wakes a day, fresh PNG from a home server—no glowing tablet.

This guide is for you and for Grok Bot. You read it to understand the system. Then you paste a prompt so your Grok Bot (Cursor / Grok Bot desktop agent with a computer) executes the setup on an always-on Mac or Pi. You do not configure servers, IPs, collectors, or cron by hand—the bot does. You buy hardware, keep the host online, connect the bot, and approve Wi‑Fi, logins, and purchases.

Your jobs (human) Buy the Hokku / Huessen frame · keep a small always-on Mac or Pi online · install Grok Bot and connect it to that machine · approve Wi‑Fi, OAuth/logins, and purchases when the bot asks.
Bot jobs Flash/firmware help with you present for Wi‑Fi · install and keep alive hokku-server · write collectors, HTML newspaper, publish pipeline · schedule editions · verify convert + show_next · fix breaks when you paste a diagnose prompt.
Privacy Kitchen-safe wall copy only (no passwords, pay, brokerage, caregiver details). Samples are fictional (Alex & Sam). Chat is newspaper input, not bot command authority, except named owners you designate.

Architecture

Tiny newsroom Grok Bot staffs:

  1. You — buy/approve; paste prompts.
  2. Grok Bot — installs and maintains the pipeline on the always-on host.
  3. Collectors — calendar, email, iMessage/WhatsApp, weather → JSON.
  4. HTML newspaper — portrait edition.
  5. Headless Chrome — 1200×1600 PNG (~40px safe margins; scale to fill, no side crop).
  6. Publish — copy into Hokku images, pin show_next, hard-fail unless convert is ok.
  7. hokku-server — serves image; frame wakes after publish (refresh_image_at_time).

Runtime data often lives under an application-support style folder for Hokku. Local UI is typically something like http://localhost:8080/hokku/ui—confirm against current Hokku docs. The bot points the frame at your host on the LAN.

Working with Grok Bot

Human checklist

  1. Buy the frame; plug in / power the always-on Mac or Pi on kitchen Wi‑Fi.
  2. Install Grok Bot / Cursor; connect the agent to that machine.
  3. Paste the setup prompt (start with “Read this guide and set it up for me”).
  4. When asked: enter Wi‑Fi, complete OAuth/logins, approve any purchase.
  5. If the frame stalls, paste the “Frame not updating” prompt.

What the bot should do (executable)

  1. Open upstream defl/hokku_epaper docs; help flash firmware (human types Wi‑Fi).
  2. Install and keep alive hokku-server (micromamba/conda + LaunchAgent or systemd).
  3. Build collectors (calendar, email, iMessage/WhatsApp, weather) → HTML → 1200×1600 PNG.
  4. Publish: pin show_next; hard-fail unless convert status is ok.
  5. Schedule morning/afternoon/evening; set wake times after publish.
  6. Verify landing (fresh mtime, convert ok, show_next) before calling a run done.
You approve Wi‑Fi credentials · calendar/email OAuth · chat-bridge access · any paid hardware or API keys. Everything else is bot grunt work.

Done looks like

  • 1200×1600 PNG, ~40px margins
  • show_next pinned; convert ok
  • Wake times after each publish window
  • Optional: last_seen after a wake
